# 产品需求梳理 Skill

[繁體中文](README.md) · **简体中文** · [English](README.en.md) · [日本語](README.ja.md)

将产品想法、访谈笔记或现有 PRD 整理成可评审、可验收的需求。先按五层漏斗搭建产品框架，再按需选用十二种提问方法，逐项澄清每个功能的九个字段。

## 在 Codex 中快速开始

1. 解压安装包，将整个 `product-requirements-discovery` 文件夹放到 Codex 的自定义 Skill 目录中。该目录通常为 `~/.codex/skills`。如果使用了自定义路径，请参阅[安装与启用说明](USAGE.md#安裝與啟用)。
2. 在新对话中选择 `$product-requirements-discovery`，粘贴下面的指令试用。也可以替换成自己的需求，并附上现有资料。

~~~text
$product-requirements-discovery
我想做公司内部会议室的自助预约，目前经常有人订到同一间会议室的同一时段。
请按五层漏斗访谈我，先整理出产品框架，再逐项问清本期功能。
~~~

## 交付内容

- **产品框架**　按目标、场景、流程、边界、验收五层排列。每层记录对应方法得出的结论及依据。
- **功能清单与九字段功能卡**　每项功能都有 ID、对应流程和优先级，字段结论可以追溯到来源。
- **验收用例与待确认事项**　使用 Given–When–Then 写明前置条件、事件和可观察结果，并列出仍需回答的问题或待定决策。
- **Markdown PRD**　要求生成 PRD 时，使用固定章节，将框架、功能规格、跨功能需求、验收条件和决策记录整合到一份文档中。
