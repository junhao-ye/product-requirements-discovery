# 十二種提問法

先定位功能卡缺的是哪個欄位，再挑能取得具體答案的方法。將括號內容換成目前功能的角色、事件、資料或規則。

| 問法 | 何時使用 | 可直接改寫的問句或動作 | 優先補查的欄位 |
|---|---|---|---|
| 蘇格拉底六問 | 需求含糊，或不同人對同一規則有不同解讀。 | 從下方六個角度挑一個對準分歧。請對方用具體案例說明怎麼判定。 | 判斷標準、邊界、來源 |
| Mom Test | 需要了解既有行為、實際損失或變通做法。 | 「上次發生［情況］時，你從哪一步開始？用了什麼工具？最後怎麼處理？」若頻率影響優先級，再問可查的近況或紀錄。 | 觸發、現狀、來源、優先級 |
| 第一性原理 | 規則或既有工具看似理所當然。 | 「要達到［結果］，哪個條件或資料確實不可少？它受什麼約束？如果拿掉目前做法，最少要保留什麼？」請對方指出約束的依據。 | 輸入、輸出、判斷標準、邊界 |
| 5 Whys | 同一問題重複出現，已有可追查的事件。 | 「這次［事件］為什麼發生？」沿上一個有證據的答案追問「造成［原因］的條件又是什麼？」遇到多條成因分開記錄，到可採取行動或證據不足時停下。 | 現狀、異常、來源 |
| XY 問題 | 對方先提出按鈕、欄位、技術或其他指定方案。 | 「你想靠［方案 Y］完成哪件事［問題 X］？上次在哪一步卡住？有沒有可比較的替代做法？」將問題和候選方案分開記錄。 | 觸發、現狀、輸出、優先級 |
| Kano 雙問 | 要了解同一使用者族群對某個候選功能的感受。 | 在相同角色與場景成對問「如果有［功能］，你有什麼感受？」及「如果沒有［功能］，你有什麼感受？」各記一個回答，追問現有替代。將成對回答當成優先級的一項證據。 | 優先級、來源 |
| 逆向思維 | 需要明確訂出不可接受的結果或狀態。 | 「這個功能最不該讓誰做到什麼？哪個結果一出現就必須攔下？被攔下的人應看到什麼？」把回答寫成禁止條件及可觀察的結果。 | 判斷標準、輸出、邊界、異常 |
| 失敗預演 | 候選流程或首版範圍已具體，仍需找最可能的失敗原因。 | 「假設上線後［流程］已失敗，最可能發生了什麼？會先看到哪個訊號？誰能復原或接手？」將想像的原因列為風險，再用案例或紀錄核對。 | 邊界、異常、優先級 |
| 極端情況 | 規則有數值、時間、身分、狀態或相依條件。 | 「剛好等於上限、少一點、多一點時，結果各是什麼？」視場景補問缺值、重複送出、事件亂序、無權限或服務中斷。 | 輸入、判斷標準、邊界、異常 |
| 現地現物 | 口頭敘述和系統或實際作業可能有落差。 | 「可以用最近一筆去識別的例子，從觸發到交接示範一次嗎？這一步實際看見了什麼？」記下可查的畫面、表單、紀錄或操作步驟。 | 觸發、現狀、輸入、輸出、來源 |
| 魔鬼代言人 | 高風險取捨、功能已被快速列為 Must，或方案缺少反方檢查。 | 「請替反對［決定］的一方說出最強理由。在哪個案例下它會帶來更大成本？看到什麼證據會讓我們改變決定？」記錄決策所依賴的條件。 | 判斷標準、邊界、優先級、來源 |
| 費曼複述 | 要核對已討論的規則，尤其是交接、例外或臨界值。 | 「我的理解是［前提］時，做［動作］會看到［結果］。如果［例外］，會變成［結果］。哪裡需要更正？」用初次操作者聽得懂的詞，記下對方確認或更正的內容及來源。 | 觸發、輸出、判斷標準、邊界、異常 |

## 蘇格拉底六問的六個角度

| 角度 | 問句 |
|---|---|
| 澄清概念 | 「你說的『有效』，在這個案例裡具體指什麼狀態？」 |
| 檢視假設 | 「我們假定每次都會有［資料］，什麼情況會缺？」 |
| 追問理由與證據 | 「哪一筆紀錄或哪項決議支持這個標準？」 |
| 檢視其他觀點 | 「改由下游接手人操作，對同一結果會有什麼要求？」 |
| 追問意涵與後果 | 「採用這條規則後，誰可能多等一步或被拒絕？」 |
| 反問問題本身 | 「為什麼現在必須決定這題？它會影響哪個決策？」 |

## 遇到高影響缺口時

- **現況、輸入、輸出或來源不清楚**。先用 Mom Test 把討論落到最近一次實例，再請對方用現地現物示範。依來源寫下觀察結果，並保留受訪者的解釋。
- **規則分歧或範圍含糊**。用蘇格拉底六問或第一性原理釐清定義與限制，用極端情況檢查臨界值，再用費曼複述核對預期結果。
- **指定方案或優先級缺少依據**。先用 XY 問題釐清待解的問題。有合適的受訪者時用 Kano 雙問取得偏好，再用魔鬼代言人檢查替代方案和延後影響。
- **失敗結果不明**。用逆向思維定出要阻擋的結果，用失敗預演找出事前沒想到的成因和接手方式。將已確認的高風險情境寫成 Given–When–Then。
