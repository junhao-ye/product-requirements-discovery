# プロダクト要件整理スキル

[繁體中文](README.md) · [简体中文](README.zh-CN.md) · [English](README.en.md) · **日本語**

プロダクトのアイデア、ヒアリングメモ、既存のプロダクト要件定義書（PRD）をもとに、レビューと検証ができる要件を整理します。まず 5 層に沿ってプロダクトの全体像をまとめます。次に、12 種類の質問手法から必要なものを選び、各機能の 9 項目を明確にします。

## Codex で始める

1. パッケージを展開し、`product-requirements-discovery` フォルダーを丸ごと Codex のスキルディレクトリに配置します。通常は `~/.codex/skills` です。独自のパスを設定している場合は、[インストールと有効化の手順](USAGE.md#安裝與啟用)を参照してください。
2. 新しいチャットで `$product-requirements-discovery` を選択し、以下のプロンプトを貼り付けます。ご自身の要件に置き換え、既存の資料を添付することもできます。

~~~text
$product-requirements-discovery
社内の会議室を社員が自分で予約できる仕組みを作りたいです。同じ会議室が同じ時間帯に二重予約されることがあります。
5 層に沿ってヒアリングし、まずプロダクトの全体像をまとめてください。その後、今回のリリース対象となる機能を一つずつ明確にしてください。
~~~

## 得られる成果物

- **プロダクトの全体像**　目的、利用シーン、フロー、対象範囲、受け入れ条件の順に整理します。各層で対応する質問手法を使って得た結論と根拠を記録します。
- **機能一覧と 9 項目の機能カード**　機能 ID、対応するフロー、優先度を示し、各項目の結論を根拠までたどれるようにします。
- **受け入れシナリオと未確認事項**　Given–When–Then 形式で前提条件、操作やイベント、観察できる結果を記述し、残っている質問や判断事項を一覧にします。
- **Markdown 形式の PRD**　PRD の作成を指定すると、定型の構成に沿って全体像、機能仕様、機能横断要件、受け入れ条件、決定事項を 1 つの文書にまとめます。
